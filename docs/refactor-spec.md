# 脚手架改造规范

## 适用范围与定位

本文约束本次对 antdv-next-admin 仓库的脚手架改造，目标是形成以 **SuperForm、api-datamodel、async-result-cache** 为核心、便于 AI 辅助业务开发的前端脚手架。

[根目录 AGENTS.md](../AGENTS.md)是脚手架使用者的长期业务开发约定；本文件单独记录本次改造要求、迁移边界和验收标准。不得把阶段状态和清理任务写回业务开发约定。

执行时同时遵守用户的工作约定，按 [本地 AI 指南入口](../AI_GUIDE.md)读取实际依赖文档。本文是要求，不代表改造已经完成。

## 改造目标

1. 所有业务页面和示例统一采用核心库的公开 API 与原生 Schema，示例能作为 AI 生成业务代码的参考。
2. 全面停用 `src/components/Pro` 和旧 Pro 配置、类型、调用方式，不以更名或兼容包装代替迁移。
3. 保留有实际价值的组件能力，转换为原生组件扩展、自定义 field 或独立展示与布局组件。
4. API 服务配置、缓存配置、接口生成产物和 facade 分层；正式业务接口使用 Codegen。
5. README、AGENTS、CLAUDE 及相关文档与最终实现一致；依赖指南只引用本地入口。

## 页面和示例迁移

- 覆盖系统管理、登录、个人中心、仪表盘及全部示例入口，逐项核对脚本、模板、类型、异步导入和路由。
- 业务表单、搜索、编辑、列表与详情使用 SuperForm / SuperTable / SuperDetail 及对应 hooks。
- 用户、角色、权限、字典、部门、配置、文件和日志等核心业务必须完成实际链路迁移，不能只通过共享 ProForm 替换渲染引擎。
- 核对复杂表单、远程选择、动态条件、主从详情、虚拟表格、上传、导入导出、状态缓存、请求鉴权等示例；样例数据和模拟场景可以保留，但不得另外建立与核心库重复的生产业务协议。
- 纯图表、编辑器、布局和工具展示不强行转换成表单；业务输入以原生扩展或自定义 field 接入。
- 保留现有业务行为、权限、国际化、回填、校验、分页和错误处理。需要改变业务语义时说明理由，不静默删掉难迁移的功能。
- 提交使用 SuperForm 返回的数据；编辑标识和上下文字段声明为 Hidden，避免回填与提交丢字段。
- 多语言文案、示例标题和说明不能继续把旧 Pro 协议作为推荐开发模式。内部翻译键或路由标识如需保留兼容，应说明原因。

## 扩展组件应当能按原生组件的方式使用和替换，统一遵循这些边界：
- 保持原生接口：沿用原生 props、事件参数、受控属性和 slots；新增能力也通过这些入口提供。
- 优先覆盖 component：复用官方 Adapter 的协议转换，仅在确有必要时保留薄的 render 适配。
- 由业务 Schema 控制：原生及扩展属性放 attrs，事件通过 attrs.onChange 等监听，内容通过 slots 配置。
- 职责保持清晰：扩展组件负责原生交互；查询、分页和 CRUD 仍由 SuperTable 管理。
  
## 原生扩展与字段补充
- SuperForm 初始化集中在 `src/setupSuperForm.ts`，应用挂载前执行一次。
- ProTable 的列设置、列宽调整、密度切换、表头筛选、排序等有价值交互放到外部增强原生 Table 组件。
- 通过初始化的 Adapter overrides 覆盖默认原生 Table 渲染，保持 SuperTable 的公开 Schema 和动作协议。
- 增强组件负责原生交互，通过标准事件与参数协同；查询、请求取消、分页、选择、编辑和 CRUD 状态继续由 SuperTable 管理。
- 不完整复制旧 ProTable 的搜索表单、数据加载和弹窗状态，不增加另一套 Table Schema。
- JSON、多语言、代码编辑器和业务选择器等按需要注册自定义 field，明确 value / model 协议，并提供属性类型声明。
- 可复用图表、状态展示、布局和弹窗原生增强可保留独立职责；迁移后不能依赖停用的 Pro 目录和类型。
- 特殊交互使用 InputSlot 时说明其必要性；普通 Select、TreeSelect 等不能批量回退旧 FormItemRender。

## API 与 Codegen

```text
src/api/
  service/          # 请求服务及全局策略
  cache/            # 缓存作用域、注册、失效配置
  generated/        # 接口 API 和生成类型，Codegen 独占
  facade/           # 生成目录之外的业务加工与缓存协调
```

- 同一请求服务集中处理地址、鉴权、令牌刷新、Mock 适配、响应转换和请求反馈。Axios 可作为传输适配器复用。
- 所有业务 API 采用 api-datamodel，不能只改部门和字典。页面、Store 和示例不继续直接使用旧 request。
- 生成配置必须限定输出到 generated 的对应服务目录，不能覆盖 service、cache 或 facade。
- 生成目录只放接口和生成类型；OpenAPI 文档、生成配置、缓存、业务包装和说明文档放在目录之外。
- 正式接口从 OpenAPI 自动生成。提供明确的生成入口和命令；不猜测未提供的后端契约。
- 示例接口需要对应示例契约和可重复生成的配置。手写快照不能标记为已执行 Codegen 的产物。
- 额外结果处理、缓存协调和接口组合放 facade；不为没有加工的每个接口机械增加 facade。
- 统一响应语义，业务调用使用服务层转换后的结果。迁移所有受影响调用方，避免一部分继续按旧响应信封读取。
- 删除旧请求和 API 入口前，确认静态、动态、Store、Mock 与示例调用都已迁移；不保留两套长期服务实现。

## 缓存

- 使用此前确认的 npm 包 `async-result-cache`，不是 async-cache-result。
- 将原来散落的缓存作用域、注册与失效配置移到 cache；生成 API 保持纯接口职责。
- 缓存字典、完整部门和常用选项，分页搜索与实时请求按需求保持实时。
- 保留并发请求合并、写后失效、会话退出清理和防止旧请求回填的边界。
- Vue Store 和字段读取同一缓存源，不用额外数组或状态层掩盖缓存失效。
- 不引入库未提供的自动过期参数。外部系统修改后的主动刷新入口应明确。

- AGENTS 仅保留长期业务开发约束，不写“迁移期间”“当前尚未改造”或本次改造清理清单。
- AI_GUIDE 只导航到实际存在的本地依赖指南，不复制正文、不使用远程指南。

- 历史接入文档不得继续宣称包装接入等于全面迁移完成；历史状态与本规范明确区分。

## next-dev API 适配（2026-10-11）

依赖基准：`nicefan/antdv-superform` 的 `next-dev`，提交 `ff912d3`。

- 全部业务和示例的 SuperTable 分页迁移至 `attrs.pagination`；全局使用 `defaultProps.SuperTable.pageTransform` 保留后端 `current/pageSize` 契约。
- 表头条件通过 `attrs.filterSortTransform` 交给 Core 保存和查询，不再维护另一份响应式 params 或从原生事件调度查询。
- Table 扩展直接消费公开 UI 状态协议，转换原生列 render、选择、展开和统一变更事件；不依赖官方渲染结果的内部 VNode 结构。
- Modal 使用固定 UI 组件覆盖及显式属性适配；Form 保留动态 Ref 解包；Upload 保留原生拖拽增强。
- 补充原生扩展公开属性类型，替换废弃的 `hideInTable`；表格示例的编辑字段直接复用 columns。
- 初始化接入内置中文/英文文案，移除覆盖所有字段的空标签占位符；启动前等待已保存语言加载，切换语言按长期约定持久化后刷新。

## 系统页面 Schema 与 CRUD 改造（2026-10-11）

- `views/system` 的用户、角色、权限、配置、字典数据、部门通过 `useTable` 和 `rowEditor` 统一编辑会话、提交状态、CRUD 与列表刷新；文件删除使用核心动作，日志清空使用带确认的业务动作。
- 每类字段只维护一份 Schema，编辑默认复用 columns；部门详情复用同一字段数组。搜索优先引用字段名，权限类型和字符串状态查询保留与编辑不同的必要配置。
- 字典类型使用 `useModalForm`，用户 CSV 导入使用核心 Upload 的 custom 模式；用户导出读取核心当前查询条件。角色权限树、部门树及父级防循环、配置值按类型编辑等业务交互保留。
- 字典、配置分组和部门节点通过响应式 params 驱动查询，移除手写刷新 key、独立弹窗可见状态、提交状态和字段镜像。缓存失效复用已有 facade，导航与公共订阅更新独立于核心列表刷新。
- 用户角色、角色权限、权限资源与操作、配置字符串值、部门提交字段的组装在 facade 完成；生成接口与生成类型未修改。
